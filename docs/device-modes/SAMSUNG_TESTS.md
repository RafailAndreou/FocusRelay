# Manual Samsung / Android verification

Run on a spare/test phone first with two-minute sessions and nonessential apps. Record model, Android/One UI version, APK commit/certificate, relay commit and exact-alarm/battery settings. These are manual checks, not claims of device testing.

- [ ] Update in place from 1.6.0 using the same signing identity. Verify selected apps, local rules, legacy blocks, remote presets/schedules and pairing survive. Apply D1 migration on a development relay and verify old records/revisions remain.
- [ ] Before local mode opt-in, MCP activation is rejected. Enabling modes does not enable actions or usage sharing and does not grant DND/brightness permissions.
- [ ] Create Thesis as an allow-list mode; allow ChatGPT and one selected app. Activate for two minutes. Check a different eligible opted-in app blocks; non-opted-in apps stay unaffected. Install/select another nonessential app and sync; dynamic complement takes effect. Uninstall/revoke opt-in and confirm it is no longer restricted.
- [ ] Try empty lists, unknown/malformed packages, mixed allow/block fields, past expiry, excessive duration, unknown mode IDs, invalid recurrence and unsupported notification policies. No partial state or acknowledgement should appear.
- [ ] Verify FocusRelay, Settings, launcher, Phone/emergency UI, SMS and keyboards remain usable. Do not place an emergency test call. Check preinstalled/system apps and your banking/authenticator/password apps; add explicit exclusions for anything essential. Test a user exclusion even if a template explicitly lists the app.
- [ ] Activate a block-list mode; only its selected eligible apps block. Add a second overlapping mode and a legacy block; ending one mode must not release the other restrictions.
- [ ] Grant one app temporary access for one minute. It opens when no other rule blocks it, then blocks again without internet. Repeat while another mode/local rule blocks the same app; the exception must not override it. Revoke by exception ID and verify original session duration/list unchanged.
- [ ] Pause/resume and verify original end time stays fixed. End Mode offline and reconnect; redelivery must not restart it. Emergency-end with queued sequence steps; none should start even after reconnect/reboot. Re-enable only intentionally.
- [ ] Create two contiguous two-minute sequence steps. Synchronize, turn on airplane mode, close UI, and observe transitions/expiry. Repeat over reboot and with screen off. Absolute times must not restart. Repeat without exact-alarm permission; status must disclose inexact scheduling/delay.
- [ ] Deny/revoke Usage Access or overlay permission while active. Status must stop claiming confirmed restrictions and show readiness errors. Overlay must release on expiry/revocation; Home/Recents navigation must work. Restore permissions and verify recovery, including an already-expired session.
- [ ] Disconnect remote control during a device action; restrictions clear and restoration runs. Force-stop while an action is active, wait past expiry, reopen; restoration must run from the journal. Repeat process death without force-stop and reboot/unlock. Background restoration cannot run while Android force-stops the app.
- [ ] Without Notification Policy Access, DND action reports an error and never silently requests permission. Grant access locally and repeat. Enable a separate user/Samsung DND mode, overlap two FocusRelay DND owners, and end each: the other owner/user DND must remain. Snooze/disable FocusRelay's rule manually; the app must respect Android's override. Repeat on Android 15+ and older supported Android 10–14 if available.
- [ ] Enable manual brightness; record baseline, run two owners with different targets, end them one at a time, verify remaining owner then baseline. Repeat with media/ringtone volumes. Manually change the controlled setting; it must remain your choice after mode end. Repeat crash between action and restore where possible; inspect event/errors without exposing credentials.
- [ ] With automatic brightness on, brightness remains automatic and reports unsupported for that action. Silent/vibrate ringtone mode stays unchanged. Fixed-volume devices report unsupported. Alarm volume is never changed. Revoke Modify system settings mid-session; journal survives and retries after permission returns.
- [ ] Request Sleep until a time within 24 hours plus alarmTime. No background alarm confirmation is claimed. Open Modes, tap Set alarm in Clock, review and confirm there. Cancel in Clock and verify FocusRelay never says alarm confirmed. Check near-midnight time and a request beyond 24 hours.
- [ ] Keep phone offline while sending a new remote command. It stays pending; currentMode/restrictions require fresh matching revision, permissions and observation. Reconnect, wait for persistence + subsequent acknowledgement. Check desired/applied revisions and observedAt. Older APK must not acknowledge mode-bearing revisions.
- [ ] Usage sharing off/permission denied: tools return unavailable. Opt in and compare today's selected-app estimates against Android Digital Wellbeing. During a mode use one app, pause, use it again, resume: mode sample excludes the observed pause. Verify scope/incomplete coverage, null unsupported launch counts, and no revoked app in cached samples.
- [ ] Query bounded remote history with a small page limit; page without duplicates. Verify activation, expiry, exception, action restore and manual override events. Blocked-opening events only represent overlays actually shown, not every launch. No message/notification/browsing contents appear.
- [ ] Repeat basic blocking and transitions with Samsung battery optimization, Sleeping apps/Deep sleeping apps and Doze. Record delays honestly; never report exact enforcement based only on server desired state.

Keep logs private and redact tokens, secrets, URLs identifying private deployments and personal app labels before attaching bug reports. Automated pure-model/JVM tests cannot validate OEM DND, Clock or background execution behavior.
